# GPT 작업 지시서 — 본편(연쇄 퀘스트) 1차 연결 (케인 지시 2026-10-04)

**시작 조건:** 직전 작업(감정 B)을 push하고 서버 빌드로 판 번호가 바뀐 **뒤에** 시작한다. 그 전에는 town.js/guild.js/ui.js를 건드리는 새 작업을 시작하지 않는다.

먼저 읽을 것: `AGENTS.md`(§9 빠른 수정 루프, **시나리오 봉인 규칙**), `docs/STATUS.md`, `docs/WORKLOG.md` 맨 아래, `docs/guild_system.md`, 그리고 봉인 파일 `src/story.md`, `src/story/bible.md`, `src/story/chains.md`. 케인은 프로그래머가 아니다. 격식체 존댓말로, 결과와 케인이 할 일만 짧게 보고한다.

## 0. 봉인 규칙 (가장 중요)
케인은 시나리오를 게임에서 처음 보려고 AI에게 몰래 짜게 했다. **읽고 게임에 반영하는 것은 허용이고, 케인에게 내용을 보여 주거나 요약하는 것은 금지**다.
- 보고, WORKLOG, STATUS, 커밋 메시지, 검사 출력, 이 문서 어디에도 **퀘스트 제목, 인물의 비밀, 줄거리, 대사를 쓰지 않는다.** "연쇄 3번까지 연결"처럼 번호와 개수만 쓴다.
- 퀘스트 데이터(제목·대사·단계·보상)는 **`src/story/` 폴더 안의 새 파일**(예: `src/story/quests.json`)에 둔다. `build.py`가 읽어서 게임에 넣는다. 일반 문서에 복사하지 않는다.
- 케인이 해보고 싶어 하면 "마을을 돌아다니며 느낌표(!) 표시를 찾아 보세요"라고만 안내한다.

## 1. 지금 상태 (STATUS.md 32행)
본편과 연쇄 퀘스트 설계(약 45개)는 봉인 파일에 뼈대로 있지만, **게임 안의 시작 트리거, 진행 상태, 보상이 연결되어 있지 않다.** 지금 하는 퀘스트는 길드 반복 의뢰뿐이다. 이번 작업은 **연쇄 퀘스트 첫 5개(번호 순)를 실제로 플레이 가능하게** 만드는 것이다. 나머지는 같은 구조로 나중에 채울 수 있게 데이터 형식만 정하고, 비워 둔다.

## 2. 만들 것
1. **퀘스트 엔진(데이터 주도):** 퀘스트 한 개 = 시작 조건(레벨, 앞 퀘스트 완료, 장소 방문 중 필요한 것), 단계 목록, 보상.
   - 단계 종류: 대화(NPC에게 말 걸기), 처치(몬스터 종류·마리 수), 수집(아이템), 방문(장소 도달), 전달.
   - 상태 저장: 진행 중·완료·단계 번호를 저장에 넣는다. **기존 저장과 호환**(퀘스트 필드가 없으면 빈 상태).
2. **NPC 표시와 대화:** 시작 가능한 NPC 머리 위에 느낌표(!), 진행 중이면 물음표(?). 대화창은 기존 `#dlg` 모양 재사용. 시나리오 장부(bible.md)의 NPC 이름·직업·위치를 따른다.
3. **퀘스트 목록:** 가방 창(캐릭터 창)에 탭 하나 추가하거나 기존 의뢰창을 확장해서 진행 중·완료 목록을 본다. 초상화 아래 의뢰 HUD(최대 3개)에 **본편은 별도 표시**(예: 금색 별)로 함께 나오게 한다.
4. **보상:** 금화, 경험치(기존 경험치 기준 함수 `targetKillsForLevel` 등과 맞춤), 아이템. 숫자는 임시값으로 넣고 보고에 적는다.
5. **대사와 문장:** chains.md는 뼈대(퀘스트당 몇 줄)다. **GPT가 짧은 코미디 톤 대사로 채운다.** 전체 이용가, 한 줄은 대화창 두 줄 이내. 주인공은 돈에 환장한 엘프 루크레아(이름은 시스템에 이미 있음).
6. **길드 재설계는 이번 범위가 아니다.** 건드리지 않는다(STATUS.md 126행에 별도 기록됨).

## 3. 하지 않는 것
스킬/VFX/소리(`sound.js`, `bgm.js`)/기본 공격 수치(`WB`)/몬스터 수치/가방·상점·창고·여관·감정 코드는 건드리지 않는다. 케인이 방금 정한 **새 인물 설정(동료·용병·빌런)은 아직 봉인 파일에 반영되기 전**이므로 이번 작업에서 만들지 않는다. 나중에 Claude가 봉인 파일에 반영한 뒤 별도 지시를 한다.

## 4. 검사·기록·올리기
- `check_quest.py`: 시작 조건 충족 시 ! 표시 → 대화로 수락 → 단계 진행(처치/수집/방문) → 완료 보상 → 저장·불러오기 → 기존 저장 호환. 출력에 퀘스트 내용(제목·대사)을 찍지 않는다(ID와 숫자만).
- 기존 검사(`check_ui/stash/sell/trade/skills/combat/save/inn`)가 계속 통과해야 한다.
- 먼저 엔진 + 퀘스트 1개를 push → 판 번호 변경 확인 → 나머지 4개를 push. 빌드가 끝날 때까지 다음 push 금지.
- 작업일지는 `docs/WORKLOG.md` 맨 아래에 **내용 없이** 쓴다(개수·구조만). `game/`은 직접 커밋하지 않는다.
